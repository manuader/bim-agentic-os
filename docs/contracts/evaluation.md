# Evaluation contract — v0.2

The approved [design](../plans/2026-10-23-evaluation-design.md) adds evaluation DTOs in `evaluation/Bim.Evaluation`; it does not migrate BIM-IR or native RPC. The CLI consumes the same C# service as the deterministic oracle tests.

`RoomObservation` contains measured clear dimensions in millimetres, element observations, references, identities, save/reopen evidence and documentation values. Individual wall thickness/height, door width, Room area, dimension width and schedule area are nullable readback measurements. Missing measurements block the corresponding criterion; aggregate declarations cannot replace them. Wall geometry is the measured inner-face segment; opening geometry is its host-face point. This is an evaluation representation, not the production geometry schema.

`RevisionObservation` binds before/after/retry/rollback snapshots, operation keys, semantic changes, document updates and revisions. Test B requires a complete Test A. A west anchor remains fixed; the width changes by400mm while depth, categories, hosts, unrelated parameters and native identities remain protected. Opening movement follows measured host movement. The reported semantic diff must match observed changes. Retry preserves the complete resulting snapshot; forced-failure rollback restores the original snapshot and revision.

`EvaluationReport.VerificationState` uses the eight repository evidence states. Criterion `Outcome` uses pass/fail/blocked/unsupported and is a separate axis. Unknown metrics have null values and an explanation. Offline `total_ms` measures evaluator orchestration; real IFC execution supplies a measured worker lifecycle time, including its test fixture/QA. Neither measures architectural correction through validated Revit documentation delivery.

Offline observations exercise the oracle with `unit-tested` provenance and `ProductAcceptance=false`, even when all synthetic checks pass. The runtime entry point owns backend provenance. `IfcExecutionOptions` supplies an explicit Python executable, the exact repository worker and a fresh absolute output directory. Bounded subprocess execution, strict protocol/version/metric/check/artifact validation and process-result agreement precede integration provenance. `BackendChecks` reports the eight required IFC proof checks; `BackendAcceptance` additionally requires every portable C# criterion to pass. Report `Counts` counts case criteria; backend checks are listed separately. No caller-supplied offline JSON gains runtime provenance.

For IFC, absent native-only annotation/view/schedule/sheet observations are unsupported and their global numeric values are nullable. Any supplied measured violation still fails. Portable Test B requires portable Test A, while complete native post-revision acceptance stays unsupported. The real IFC save/reopen check is separate from the native RVT criterion. Full `ProductAcceptance` remains false and exit2 despite successful portable IFC acceptance. Revit's complete fixture path remains blocked; historical primitive success is not imported as current execution.

The PowerShell entry point is `scripts/evaluate.ps1 -Backend ifc|revit`. Build logs are separate from JSON stdout, and the output directory contains `report.json`. Exit0 requires all mandatory criteria to pass; exit1 means measured violation; exit2 means mandatory prerequisites are blocked/unsupported. IFC cannot satisfy native Revit annotation, sheet or RVT save/reopen requirements. A green engineering CI checks the machine, not full backend product acceptance.

ADR0006 now authorizes the isolated optional IFC dependency; [IFC runtime](../ifc.md) documents its real fixed-fixture execution and limitations. It does not execute arbitrary BIM-IR or the C# incremental compiler. The native implementation currently supports level/wall primitives and their recorded rollback/checkpoint tests, not full hosted elements or documentation. See [STATE](../agent/STATE.md), [BLOCKERS](../agent/BLOCKERS.md) and the [native VM procedure](../agent/NATIVE_VM.md).
